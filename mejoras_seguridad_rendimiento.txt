AUDITORÍA PROFUNDA DE SEGURIDAD Y RENDIMIENTO
==============================================
Fecha: 2026-04-11
Estado: REVISIÓN EXHAUSTIVA DE CÓDIGO (Hardening Nivel 2)

---
🛡️ SEGURIDAD: VULNERABILIDADES DETECTADAS Y MEJORAS
---

[CRÍTICO] XSS (Cross-Site Scripting) EN IMPORTACIÓN MASIVA:
  - Localización: app/routes/trabajadores.py (función procesar_importacion) y plantilla importar_empleados.html.
  - Riesgo: Se usa el filtro '| safe' en Jinja2 para mostrar errores de Excel. Un atacante puede poner código Javascript en una celda (ej. un RFC falso con un script) y este se ejecutará en la sesión del administrador al ver los errores.
  - Solución: Eliminar '| safe' o sanitizar los nombres de las columnas y valores de las celdas antes de incluirlos en el mensaje de error.

[ALTO] PII (PERSONAL IDENTIFIABLE INFORMATION) SIN CIFRAR:
  - Localización: app/models.py (Tabla Trabajador: rfc, curp, nss, domicilio).
  - Riesgo: En caso de una brecha en la base de datos (SQL Dump), toda la información de identidad de los empleados queda expuesta.
  - Solución: Usar cifrado simétrico (como AES via la librería 'cryptography') para estos 4 campos. La app los cifra al guardar y los descifra al mostrar.

[ALTO] EXPOSICIÓN DE DATOS SENSIBLES A ROLES NO-ADMIN:
  - Localización: app/routes/trabajadores.py (get_trabajador).
  - Riesgo: Los coordinadores tienen acceso a ver el RFC y CURP completo de los empleados.
  - Solución: Implementar una función de "masking" que oculte los caracteres centrales de estos campos para roles que no sean 'admin' o 'super_admin'.

[MEDIO] ID ENUMERATION (IDOR):
  - Localización: Todas las rutas de tipo /trabajadores/editar/<int:id>.
  - Riesgo: Es fácil predecir que si existe el ID 100, existe el 101. 
  - Solución: Migrar a UUID4 para identificadores externos.

[MEDIO] FALTA DE MFA (2FA) MANDATORIO:
  - Localización: app/routes/auth.py.
  - Riesgo: El 2FA es opcional. Un administrador con contraseña débil es un punto de entrada fácil.
  - Solución: Forzar la activación de 2FA para cualquier usuario con rol 'admin' o 'super_admin' antes de permitirles ver el dashboard.

[BAJO] API DOCUMENTATION LEAK:
  - Localización: run.py (FastAPI mount).
  - Riesgo: Swagger UI expone todos los endpoints y sus estructuras.
  - Solución: Desactivar 'docs_url' y 'redoc_url' de FastAPI cuando FLASK_ENV == 'production'.

---
🚀 RENDIMIENTO: CUUELLOS DE BOTELLA IDENTIFICADOS
---

[ALTO] OPTIMIZACIÓN DE N+1 EN DASHBOARD Y LISTAS:
  - Problema: 'index()' en trabajadores.py carga relaciones 'credenciales' y 'documentos' de forma ineficiente si no se usa selectinload (ya lo empezamos a corregir, pero falta en otros blueprints).
  - Solución: Auditar todos los blueprints y asegurar que se use eager loading en cada consulta que se use en un bucle 'for' de Jinja2.

[ALTO] MINIATURAS DE FOTOS (THUMBNAILS):
  - Problema: El sistema carga la foto original (ej. 4MB) incluso en la lista de trabajadores donde solo se ve un círculo de 40px.
  - Solución: Generar una versión 'thumbnail' de 100x100px al momento de la subida y usar esta en las listas.

[MEDIO] ÍNDICES ESTRATÉGICOS:
  - Mejora: Agregar índices compuestos en PostgreSQL para búsquedas:
    - (id, activo) en Trabajadores.
    - (categoria, activo) en Productos.

[MEDIO] SESSION DATA EN REDIS:
  - Mejora: Mover el almacenamiento de sesiones de Flask (Client-side Cookies) a Redis (Server-side) para reducir el tamaño de las cabeceras HTTP y mejorar la seguridad.

---
PRÓXIMAS ACCIONES RECOMENDADAS:
1. Arreglar el XSS en la importación de Excel (URGENTE).
2. Implementar masking de PII para coordinadores.
3. Configurar UUIDs para nuevas tablas y migrar las existentes.
